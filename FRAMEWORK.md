# Liquid portfolio framework

Content, card rendering, placement, navigation, and material motion have separate owners.

## Content and cards

`content/catalog.json` owns the versioned canonical content catalog. Document types include portfolio items, pages, news and reusable components. Documents compose typed text, media, info-card, carousel, reference, metric and quote blocks. Media and documents are referenced by stable IDs. `dist/content/model.js` defines the CMS-neutral schema and reference validation; the build exports published-only snapshots. `dist/content/provider.js` supplies immutable stores, provider adapters, filtered retrieval and typed answer resolution. See [CONTENT_MODEL.md](CONTENT_MODEL.md) for contracts, examples and migration boundaries.

`dist/documents.js` is the compatibility projection into the existing card/motion system. Repeated cards are placements referencing the same canonical project. Each keeps its existing route/DOM ID. `dist/home-content.js` reads the home, news and footer documents. News remains outside project navigation; Current places it after the work and information cards, while Flip and Flat hide it.

`dist/card-renderer.js` shares card rendering across layout placements, document references and future AI results. `dist/content-blocks.js` renders registered block types on a configurable 1–4 column detail grid; mobile collapses the grid. Text and media URLs are escaped at rendering boundaries. Content does not own motion state.

Project `summary` supplies the short card description/results. Project `context` supplies the separate longer introduction beneath the detail heading. Details do not prepend the card summary. The full context uses the same paragraph fade and individually staggered sections on every project entry, including the homepage and next/previous navigation; differing card/detail descriptions crossfade while matching client names and headings retain their shared-element transition. Shared headings bypass the introductory fade independently of paragraph content, so a visible carousel caption cannot be misclassified as a hidden destination.

## Placement

`dist/home-layout.js` owns a flat map of persistent card slots. It moves the same elements between adapters without rebuilding their contents or replacing their WebGL image canvases.

`dist/card-gallery.js` is a reusable gallery, independent of homepage layouts. Developer settings → Layout → Product display chooses Cards or Carousel, defaults to Carousel, and persists as `prem-home-product-display` (also included in preset import/export). The homepage `home-projects` block references the six canonical projects. Cards mode keeps the existing Current/Flip/Flat adapters and their preferences; Carousel uses the reusable circular gallery. Both presentations remain in the live DOM when toggled, and homepage return retains gallery controllers together with the card/image scene. About replaces its project gallery with the structured `about-timeline` block, mounted by the same `HeroTimeline` controller as the optional homepage timeline. Its circular adapter spreads cards across a front-facing arc. `dist/gallery-extrusion.js` adds physical CSS 3D side faces around the fitted image or styled card perimeter; the rounded edge remains visible when the front is edge-on. The screen is the front surface at z=0, and thickness extends behind it. Clockwise perimeter faces have outward normals and hide their backfaces, so an angled view cannot show both opposing side walls. Opacity applies separately to the front and side faces so the 3D mesh is not flattened.

Gallery project links enter the same shared-element morph as homepage and Chat cards. The visible gallery caption supplies the client, title and description endpoints. Opening retains the source page, gallery controllers, decoded images and scroll position; returning restores those same elements. `dist/project-entry-memory.js` records the entry route independently of Chat history, survives next/previous project changes, and rolls back when Escape reverses a transition.

- **Current:** Regular aligns card heights within each grid row. Masonry uses measured row spans to follow each card's content. Both use native CSS Grid with a configurable 1–4 column count; the default remains two columns. A single column is centered, and narrow screens cap the column count.
- **Flip:** a vertical sequence of CSS 3D cards. A sticky left hero begins with the introduction. As the page scrolls, the active project replaces the hero H1 and supporting copy. Scroll position drives perspective, scale, opacity, and the active item. A neutral region keeps the spotlight card face-on; hysteresis prevents rapid description changes at boundaries.
- **Flat:** the same sticky left hero and spotlight selection, beside one natural column of Current cards. Desktop column proportions favour cards: `--flat-text-column` is .88fr and `--flat-card-column` is 1.12fr. Regular and Masonry image proportions remain available. This mode applies no perspective, scaling or opacity poses, and does not start the scroll material animation loop.

The Homepage layout dropdown in Glass studio settings switches between Current grid, Flip and Two columns · Flat cards. Current and Flat also have a Regular/Masonry switch. Grid columns are in Glass studio settings. View, arrangement, and column preferences persist locally. In Current grid with one column, the card composition control places the existing description above, below, left, right, or alternates left/right across projects. Side compositions use equal image and copy tracks; on narrow screens they fall back to a stacked card. The same project nodes and image contexts are retained when switching compositions. `dist/tokens.css` is the shared source for semantic colours, glass values, spacing, type, card radii, gaps, and page layout. `dist/style.css` consumes these tokens, while studio controls can override card radius and gap; those choices persist locally. Glass studio also offers full-bleed home card images, a switch to show only content on home and detail cards (including full-bleed cards; the complete shell, reflections, rim, shadow, and afterglow are hidden), independent top, bottom, left, and right page-edge shades, a shared shade-depth control, and a switch to hide the logo and tagline. Edge shades fade content into the active light or dark page colour, and all shade controls persist locally. The default-on “Move edge shades away on details” toggle hides the overlay on detail routes without changing saved side switches or depth. `dist/edge-shades.js` fades the overlay and translates each edge outward by its own depth (top up, bottom down, left left, right right). Opening and returning share the card morph clock; Escape reverses the same animations, and the final route state is committed before cancelling animation fills. Direct links and reduced motion apply the destination immediately. Turning this toggle off keeps configured shades on every page. Full-bleed mode changes image placement on the existing cards, preserving their image contexts; the image shade and shared text colours interpolate into the detail view. These appearance preferences persist locally.

## Featured stage and project backdrops

Two developer settings (both off by default, saved locally and included in settings export) add a photographic backdrop per project.

- **Featured stage** (Layout → Featured stage, `prem-feature-stage`) applies to Current layout in Cards mode above 700px. It forces one column and suspends Alternating rows. Each featured project (`featured: true` on its home placement; every home project is currently featured) becomes a full-viewport row: its backdrop bleeds to both screen edges, outside the content rail, with the copy on the left and the product screenshot on the right at `--image-max-width-landscape`, the same width as a single wide Alternating card. The card shell, glass skin and image backing are dropped so only the screenshot floats, and each backdrop fades at its top and bottom edges (`--feature-stage-fade`) so consecutive stages blend. Stages are at least one viewport tall with `--feature-stage-padding-block` above and below. `HomeLayout.setFeatureStage()` owns the mode; `card-renderer.js` always writes a `.card-backdrop` and CSS shows it only for staged cards, so hidden backdrops are never fetched.
- **Note cards.** Under each staged project's copy and screenshot sit its `homeCards` (see [CONTENT_MODEL.md](CONTENT_MODEL.md)): three roomy cards (`.note-card`), each with a smaller rounded image or muted looping video inside and a title and description only when authored. They are always in the markup and shown only in this mode (`note-cards.css`), so hidden media is never fetched. With cards the stage becomes two grid rows: the full-viewport copy and screenshot row, then the cards. The backdrop is pinned to the first row (`grid-row:1/2`, so it covers that row and the top padding but not the cards, which sit on the plain page). The case-study pages will reuse the card structure with `detailCards`.
- **Stage reveal.** `feature-stage-reveal.js` observes the staged cards. When a card is a quarter in view it gets `data-stage-in-view` and its photo settles from 1.06 scale while the screenshot rises 14px and grows from 0.94 (see [MOTION.md](MOTION.md)). A card that has fully left the screen resets instantly, so the reveal replays on every scroll down. The hidden start state applies only while the gallery carries `data-stage-reveal`, so a failed script leaves every stage visible. Reduced motion and Animation Off show stages at rest.
- **Project backdrop image** (Project details → Project backdrop image, `prem-project-backdrop`) shows the project's photo behind its detail page. `project-backdrop.js` owns one fixed layer behind the page. It fades in from 1.06 scale, crossfades when Next/Previous changes project, leaves on the exit timing, and drifts with scroll (0.08×, capped at 8% of the viewport) while a backdrop is showing. A wash of the page colour keeps copy legible in both themes. It always loads the largest copy, because covering a viewport crops a wide panorama to about three viewport-heights.
- **Data and files.** A project links a backdrop with `presentations[].card.backgroundMediaId` (an image asset id); projects without one use the `generic-bg` asset. See [CONTENT_MODEL.md](CONTENT_MODEL.md) and [MEDIA_ASSETS.md](MEDIA_ASSETS.md) for the asset rules and the copy pipeline.

## Card copy: client position and card details

Settings → Cards has two switches beside the existing "Client leads the title" (all default off, saved and exported).

- **Client above the title** (`prem-card-client-above`, `body.card-client-above`): the client sits on top in capitals with wide tracking (`--client-eyebrow-tracking`). It wins over Inline because its rules come later at equal weight and it hides the inline prefix.
- **Card details** (`prem-card-details`, `body.card-details`): adds a status pill (the project's `projectStatus`) above the client, turns the results line (the card's `summary`) into gradient text, and adds a discipline tag row (`disciplines`) at the bottom in the eyebrow role (`.text-eyebrow`).
- **Show category instead of title** (`prem-card-show-category`): replaces the card heading text with the project's `shortCategory` (fallback `name`). The `<h2>` stays, so Client above the title and every card-copy style still apply; carousel captions use the same markup. `applyCardTextSource()` in `app.js` swaps the text from `data-title` / `data-category`.
- **Content starts in the first column** (`prem-content-start-first`, off): home sections sit on a three-column grid and their content normally skips the first column (`--content-column-start: 2`). On, the root class `content-start-first` sets it to 1, so content (one or two columns wide, as before) starts on the first column and section headings stack above it.
- **Character opens the assistant** (`prem-character-assistant`, on): when the menu fills the dock (not the composer), the Assistant button and the index button are hidden and the dock character becomes the button (role button, focusable, Enter/Space/click open the assistant as the button would). Off restores both buttons. Depends on the agent (`agent.js`).
- **Chat width** (`prem-chat-width`, Developer settings → Layout → Page template widths → Chat): Default keeps the chat column as it was (900px, or the composer's width in the menu-dock chat); Extra small, Small, Medium or Large set `--chat-width` to the shared preset, for the column and, in the menu-dock chat, the composer pill under it.
- **Chat page: composer under the welcome** (`prem-chat-inline-composer`, on): with the menu in the dock (contextual composer off, contextual buttons inline), the chat page keeps the menu in the dock and moves the composer (`#askForm`) into the page (`#assistantInlineComposer`) under the welcome, as its own glass pill that follows the conversation and sticks to the bottom; leaving the chat page puts it back in the dock. A `#assistantMascot` stage above the welcome is where the character sits. Composer styles use `:is(#dock,.assistant-inline-composer) .assistant-composer`, which keeps their specificity.
- **Assistant opens as** (`prem-assistant-presentation`): Chat page (default), Floating panel above the dock, or **Sidebar**. The sidebar (`assistant-floating.css`, root class `assistant-sidebar-open`) docks the conversation to the right edge, pushes the page and fixed header aside (`body`/`header` shrink by `--assistant-sidebar-width`) and moves the dock's composer to the sidebar's foot by narrowing `--composer-max-width` (registered `@property`, read by `dock-morph.js`). Escape, close and maximise work as in the panel.
- Both stack the copy in one column (`display:flex`); the default layout is unchanged. The pill and tags are always in the markup (`card-renderer.js`) and hidden by CSS until Card details is on. Rules live in `card-details.css`.

## Home hero, header and navigation

- **Header.** The logo link is the About portrait (`assets/prem.jpg`) as a round avatar (`.brand-avatar`, `--brand-avatar-size`), and the tagline beside it is the name. Settings → Navigation → Hide logo & tagline hides both; the markup is otherwise unchanged.
- **Footer.** Settings → Content has **Show footer** (`prem-show-footer`, default on) beside the existing contact-links switch. It hides the whole site footer on every route. `syncRouteChrome` re-applies it on each navigation, so a route change cannot bring it back.
- **Phone carousel.** At 600px and below the home carousel card is as wide as the canvas minus `--gallery-mobile-inset-landscape` (32px; portrait 48px), with `--gallery-mobile-gap` (24px) between cards, and the saved Carousel size cannot shrink it below `--gallery-mobile-scale-floor` (1 = full width). Before this, a saved Size of 70% left a 390px phone with a 239px card. `--hero-gap` and `--overview-column-gap` also tighten in the phone token block so the carousel starts higher. Desktop keeps the saved settings.
- **Hero heading.** The hero `h1` has a Content Home switch, **Hero heading (h1)** (default on). It applies to the Current layout only: Flip and Flat write the active project's name into the same `h1`, so `home-sections.css` and `design-system.css` keep it visible there. Hiding it removes the page's only top-level heading from assistive technology, so use it deliberately.
- **Available badge.** The hero's status pill (`home.badge`) has a Content Home switch, **Available badge** (default on, since it is shown today; saved with the other section choices). It hides through `data-home-section="available"`.
- **Header spacing and role.** `--header-top-offset` (about 3.5vh, 16–44px) makes the header taller by padding, so the logo, name, top navigation and the agent beside it sit lower. The same token feeds `--dock-top` (the top navigation) and the hero's start, so they move together; `--header-total` is the header's full space. The header shows the name with `Product designer & builder` under it (`.brand-role`, the same size as the name, in the muted colour); Hide logo & tagline hides both.
- **Empty hero.** When the home page shows no hero heading, badge, strapline, description or At a glance and the carousel is showing (Current layout), `empty-hero.css` drops the hero and centres the carousel in the space below the header. The hero's padding used to clear the header, so the carousel takes over that margin. The carousel's box has empty space above the cards while the captions and arrows hang below, so a bottom padding of twice `--empty-hero-lift` (5vh, 24–56px) raises the visible content (cards, captions, arrows) slightly above the exact middle: measured 22px above on desktop and phone.
- **Strapline.** A one-line `home-strapline` text block on the `home` document renders as `.hero-strapline` under the hero heading. The Content Home switch **Strapline** shows it (default off). While it is visible the heading gives up its bottom margin so the strapline sits close beneath it.
- **At a glance.** The `home-overview` component document renders three columns (Recently, Experience, Writing) under the hero through `home-overview.js`. References take their wording and links from the referenced project or article. The Content Home switch **At a glance** shows it (default off). Its column titles are the eyebrow role (`.text-eyebrow`) and the items are ordinary body text ([DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)).
- **Hero spacing.** `--hero-gap` is the one value for the gap from the header's content to the hero and from the hero to At a glance.
- **Plain cards.** Settings → Cards → **Plain cards** (`prem-plain-cards`, root `data-plain-cards="on"`, default off) removes the card styling that **Card background** leaves behind: with the background off a card still shows its glass skin gradient, the inner reflections (`.material-reflection`) and the image's inner-edge glow (`.image-edge`). `plain-cards.css` removes the shell, skin, reflections, edge glow, shadows, borders, blur, the hover-effect layer and the note-card panels on every `.surface` (home cards, detail cards, information cards). Images, text and layout are untouched. `!important` is used because those layers come from long glass-style and skin selectors and inline motion styles; it is confined to this mode.
- **Plain navigation.** Settings → Navigation → **Plain navigation · text links only** (`prem-plain-nav`, root `data-plain-nav="on"`, default off) turns the dock and the buttons into plain text links: `plain-nav.css` removes backgrounds, borders, shadows and blur from the dock's links, the Back, Previous/Next, menu and Assistant buttons, the corner buttons, "View prototype" and the gallery and rail controls, and hides the dock's glass and outline. Labels and icons stay; the active page is underlined. The chat composer keeps its glass, because it is an input. The rules use `!important` to beat the glass-style rules (ids and long selectors), confined to this mode.
- **Navigation position.** Settings → Navigation → Position (`prem-nav-position`, `data-nav-position` on the root) places the dock at the bottom or centred in the header row at the top. At the top, the dock's attached menus still open upward and are largely off screen; treat Top as a preview until the menus open downward.
- **Article header.** A blog article's title sits at the page's content start (top left, like any page), then the date (no author), then the series line; only the text below is centred in the reading column. **Article title: body text size** (`prem-article-title-body`, off) sets the title at body size.
- **Title strength.** A card's title line and a project page's caption title are the strongest text (`--card-title-rest-strength` 100%, `--ink`), above the results line under them.
- **Details title beside image** (`prem-detail-heading-beside`): on, a project page leads with a card-style caption (`Merlin. AI financial analysis`, then the card's results line; `detailCaption()` in `card-renderer.js`), the image runs across the whole page under it, and the client, long title, summary and facts follow in a reading-width column (`--content-width-reading`). The caption is always in the markup and shown only when the setting is on, so the setting still switches live. Off: the original heading-then-image layout.
- **About heading switch** (Developer settings → Content About → Heading, `title` in `prem-about-content`, on): hides only "Hello, I'm Prem"; the intro text and portrait stay, and the text starts where the heading did (`.about-hero-copy>h1[hidden]+.info-body` in `about-page.css`).
- **Header on detail pages (nav on top).** With `navPosition` top, a project or article page staggers the header's avatar, then name, sliding left and fading out, then Go Back, Previous and Next (`#headerDetailNav`; Previous/Next only on projects) sliding in from the right at the same spot; leaving reverses the order. Each element moves `--header-swap-shift` (12px) over `--header-swap-duration` (240ms), `--header-swap-step` (60ms) after the one before; the order lives in each element's `--swap-in` / `--swap-out`. The dock then shows no Back pill or side arrows, and the composer row drops Back/Previous/Next. Menu links are body text (`--font-size-body`), like the name; the Nav font size slider is hidden because it no longer applies.
- **Menu on top, right-aligned.** With the nav on top the menu dock is right-aligned to the content edge (`right` follows the header's content edge, `--content-shell-width` and `--content-gutter`), so it is the rightmost container; the Assistant button sits on its left. The character takes the room beside the menu, and when the right side has none (`homeSeat` in `agent-world.js`) it hangs off the menu's left side. Bottom nav stays centred.
- **Page intro block.** Every page's title and text sit in a block `--page-intro-width` wide (50% of the content width; 100% under 1000px): the Home hero (title and a text block starting on the first or, with Content starts in the first column off, the second third), About (its hero's text column), the Lab, Contact and blog titles. The block governs the width; the title and text inside carry no cap of their own.
- **Navigation and contextual actions.** Two independent settings. **Navigation** (`prem-contextual-composer`, the "Navigation: composer (off: classic nav)" switch) is Composer or Classic nav. **Contextual actions** (`prem-contextual-buttons`: `composer` = Above the dock, `inline` = Within the page) applies to both. Above the dock, the row over the dock holds View project and the carousel arrows, View prototype, Watch and Full screen, and the page hides its own copies (`data-contextual-placement="above"`). Within the page, the row drops those (`PAGE_ACTIONS` in `composer-context.js`), the carousel shows its own controls and project pages show View prototype, Watch and Full screen in `.detail-media-actions`. Previous/Next project and Go Back stay where the nav mode puts them: on the dock in classic nav, in the row in composer mode. Contextual actions no longer switch the dock to the composer.
- **Menu link tones.** Idle links use `--nav-link-ink` and the current page `--nav-link-active-ink` (the muted text tone), each a step quieter than before, in the glass menu and in Plain navigation alike; hover and focus, including on the current page, still go to full ink.
- **Menu rhythm.** Menu links sit in the composer's inset (`--composer-control-inset`) at the composer buttons' height (`--nav-icon-size`); the selected and hovered link wear the composer buttons' glass when Glass style is on. The menu dock's width is its visible links plus that inset (`navContentWidth()` in `app.js`), never narrower than the old 252px base, so a fourth link or larger item padding cannot overflow it.
- **Dock glass.** The menu dock and the composer dock wear the same dark dock glass (the menu used to take the Assistant button's lighter glass-button fill; removed 2026-10-27 so the two modes match).
- **Back pill.** Only the assistant and project pages show it (`showBackControl` in `app.js`); About and Contact are items of the dock menu itself, so with the menu visible the dock does not change shape there.
- **Back button outline.** `backGeometry()` in `dock-morph.js` splices the back pill into the dock outline by matching the left edge's path text. The match must start at a number boundary (a leading space): with fully round ends and a pill width ending in 0 (for example 260px), the left-edge text also matched the right edge and drew a sliver across the dock during Back. `tests/dock-morph.mjs` covers it.

## Lab page

The Lab is the in-app route `#lab` (ADR-011): a content page with its own heading (`lab-page.js`: "Experiments" and one line of body text, in About's structure and sharing its `.info-body` rules), then the home page's project cards; the home hero and home sections are hidden (`main.lab-canvas` in `lab.css`). The cards follow the Lab's own rules in Developer settings → Layout → Lab (`lab-settings.js`, read by `labView()` in `app.js`): card arrangement (Masonry by default, or Regular), grid columns (4), featured cards larger (off) and show card details (on; off hides every card's copy for an images-only grid) show title (`prem-lab-heading`, on; off hides "Experiments" only, its text stays and starts where the title did) and grid full width (`prem-lab-full-width`, off; on makes the grid span the app canvas less the gutters, the same breakout as a section set to "app", so it never exceeds `--app-max-width`, 1920px). They override the global card settings on the Lab only; Work, its carousel and the Columns, Layout and Product display choices are left alone. **Featured cards larger (masonry)** (`prem-featured-larger`, on) is the global switch: off places featured cards like any other, one column wide with portraits two rows tall, so masonry wraps cards around them. A portrait image in a masonry card is capped to the height its card leaves free (`masonryImageRoom` in `image-frame.js`), so it never spills into the card below. `lab.html` only redirects to `./#lab`. The Lab link sits right after Work in the dock (`data-nav="lab"`) and after Home in the site menu, and the command `route.lab` opens it. Entering or leaving it always takes the simple page transition. The click answers at once with a short ring (to the `LAB_RIPPLE.handoff` point, never awaited, so nothing is delayed); the old page fades out and the Lab fades in as usual, and then a full ripple would land on it, but that second ring is switched off (`LAB_RIPPLE.landing`, currently `false`); leaving the Lab is the ordinary fade:

- `lab-transition.js` exports `createLabRipple()`: `click()` runs one expanding ring from the last press (or the focused control) to the handoff and clears it, `land()` runs the whole ring across the landed page. Timings are `LAB_RIPPLE` in `motion-tokens.js`. Reduced motion skips both rings.
- `lab-filter.js` builds the ring as an SVG displacement map (rendered once on a canvas, scaled each frame) and displaces the red, green and blue channels by slightly different amounts, so the colour fringe appears only along the ring. Three filters (`#main`, header, footer) are attached only while the ring is moving.
- Opening a project from the Lab fades rather than morphing from its card (no home scene is retained), and Back returns to the Lab. The composer's attach button (`#assistantAttach`) is hidden the same way, with a `[hidden]` rule in `portfolio-assistant.css` because the composer's own styles force its buttons visible.

## Geometry and motion

`#about-sphere` adds a rotatable spherical arrangement to the shared `CardWorld`
engine. `card-sphere.js` reuses its images, textures, rounded material and picking;
`card-sphere-layout.js` distributes permanent slots evenly across the sphere.
Drag, wheel and focused arrow keys rotate it; inertia is capped and reduced motion
stops it at release. Selecting any card pauses rotation and opens a centred viewer.
`card-sphere-pose.js` captures its mesh/camera projection as a CSS matrix; closing
reuses that same matrix before revealing the original mesh. Escape reverses an
opening viewer. Project cards also offer a link to the existing project route.
The existing keyboard links and WebGL fallback remain available. Its optional
`isMoving()` hook and `CardWorld.invalidate()` render only on input, image loading
or active inertia; the settled sphere has no animation loop.

The opt-in **Hero carousel · scroll into grid** switch in Glass studio applies
to Current grid and persists as `prem-hero-carousel`. The introduction keeps
its existing layout. `dist/hero-carousel.js` places the same project carriers
in a lower hero strip while their slots reserve the native grid bounds. The
row drifts gently, pauses on hover/focus, and supports horizontal wheel, drag
and arrows. Page scroll freezes the row and interpolates translation and scale
to the measured grid; the endpoint removes transforms. Reverse scroll gathers
the cards again. Horizontal position survives detail navigation, which pauses
the carousel clock. Split layouts suspend this gate. Resize remeasures the
slots, and reduced motion disables drift and applies an immediate handoff.

Card titles have no size setting: they are always body size (`--font-size-body`) on Regular, Masonry, Flip, carousel, full-bleed and chat cards, and detail pages use the heading size. Shared-title morphs read the resulting computed size and interpolate the computed line-height ratio alongside font size and tracking. Opening, returning and Escape reach the receiving heading’s typography before handoff.

`dist/placement.js` describes screen bounds, local size, transform, and coordinate space. The Flip adapter straightens a selected card before handing it to the shared liquid morph. This is the explicit bridge between perspective placement and the existing screen-space detail transition.

`dist/motion-material.js` owns velocity-driven deformation, reflections, glow, and image trails. Flip scrolling activates it until the placement motion finishes; idle layouts have no continuing animation loop.

Every project image sits centred in a framed visual container on home cards, project details, and morph overlays. Current view uses width-driven image frames: Regular gives both orientations the same 8:5 holding frame; Masonry keeps landscape frames at 8:5 and enlarges portrait frames to 3:4. Landscape screenshots span the available image width, while portrait screenshots remain centred and become larger in Masonry. These frame ratios live in `dist/tokens.css`. Portrait and landscape sources keep their own proportions. The liquid canvas uses transparent letterboxing so refraction never crops or stretches the source. Flip cards use content-driven height with responsive minimums so headings and footers remain inside the card.

`dist/transition-control.js` owns reversible transactions and waits for all moving layers, including animations reversed after finishing. `dist/retained-home.js` preserves live home cards, canvases, handlers, layout classes, and sticky placement until navigation commits. Escape restores those objects rather than rebuilding the homepage.

## Extending the framework

`dist/image-frame.js` centres and sizes the native screenshot itself, with proportional rounded corners independent of the holding frame. The WebGL mask uses these same contained image bounds, so rounding survives refraction and morphing. Inset and detail holding frames are transparent. Full-bleed home cards have independent top padding and a shared side/bottom image padding, plus optional solid image backing and a colour picker. These controls work in Regular, Masonry and Flip, persist as `prem-bleed-image`, and remain visible when card styling is hidden. Defaults reserve 128px above the image, with zero side/bottom padding and a dark solid backing (`#0a0911`). The solid backing takes its colour directly from each card background and stays independent of card shell styling. The title shade remains a separate dark overlay. The shared side/bottom slider keeps the lower and side image insets equal. The title shade follows the measured title/eyebrow area, fades out beneath it, and has no bottom shade. Opposing padding is clamped at small sizes; the complete screenshot stays centred within the remaining space without cropping or stretching. Padding and backing interpolate to the transparent detail frame during morphs. Portrait detail heroes inherit the selected Regular/Masonry arrangement, including offscreen neighbours prepared for dragging; Masonry uses a taller 3:4 frame on details as well.

A new layout adapter supplies placement, focus, preparation for opening, pause/resume, and cleanup. Documents, renderers, routing, and material settings remain shared. ## Theme surfaces

`dist/tokens.css` owns `--page`/`--page-rgb`, neutral `--card-surface`/`--card-surface-rgb`, `--card-hover-tint`, `--surface-hover-in-duration` / `--surface-hover-out-duration`, and `--card-reflection-scale` separately for light and dark mode. Dark mode uses an almost-black canvas and softly lifted neutral cards; light mode keeps its existing page colour. The renderer derives two OKLCH hues from each document’s existing gradient. Both themes use the same 155° two-stop gradient with Oklab spatial interpolation: light hover is L .93 / C .045, dark hover is L .235 / C .018. `--card-hover-lightness` and `--card-hover-chroma` tune these independently, with typed `--surface-fill` and `--surface-fill-end` properties providing native hover interpolation. The reusable effect recipe in `dist/surface-hover.css` applies through `data-hover-effect="tint"`; `blur` and `scale` can be composed as space-separated names on any prepared surface. `configureSurfaceHover` sets the resting fill and enabled state without changing the recipe. `mountSurfaceRenderer` offers an optional canvas/shader plane in the same liquid skin, with active-state and cleanup hooks. No canvas or animation loop runs for the current tint effect. Colour enters in 240ms and fades back over 1000ms after hover or keyboard focus ends, leaving a longer tail. Re-entry retargets the current colours with no restart or added animation loop. Core semantic theme tokens are authored in OKLCH, preserving their prior appearance; RGB companion channels remain for existing alpha overlays and rendering transport. On desktop with a precise pointer, card titles and eyebrows rest at `--card-label-rest-strength` (58% ink) and transition to full ink on hover or keyboard focus. Detail heroes retain the same theme-adjusted project gradient at rest, including direct links and the offscreen neighbours used for next/previous dragging. Grid skins and morph skins share `--glass-edge` and the same reflection opacity. `--card-glow-rgb` and `--card-glow-scale` keep motion wakes neutral and subdued in dark mode. A single `--glass-edge` draws only the top highlight and bottom shade on the moving skin, with no surrounding ring or chromatic rim. Legacy parent/pseudo-element frames and image-container rims are removed; only the contained screenshot retains its own hairline. Stretch physics remain unchanged. The transition wake also respects the Afterglow control and liquid intensity. Morphs snapshot both resolved gradient stops and interpolate them through expansion, return and Escape, including full-bleed image gap backing. Colours are normalized once per endpoint; no additional shader or idle loop is introduced. Morphs interpolate the actual source and destination fills, including on Escape, without a separate animation loop or new image effect.

The Glass studio's **Card hover effect** dropdown offers four persistent recipes: current three-lobe `reveal` (Liquid morph), the previous broad two-lobe `reveal-soft`, original CSS `tint`, and `glow`. # Loading and media

The first paint uses one generated `site.css` bundle in the authored cascade
order. `scripts/build-worker.mjs` rebuilds it from `scripts/client-styles.mjs`
before packaging. The app module and content catalog are discovered early with
module preloads.

`scripts/optimise-images.py` creates responsive WebP copies and
`dist/image-variants.js` from the content assets. Run it after adding or replacing
images. Canonical originals remain available. The shared card and content
renderers reserve original image dimensions and pass deferred sources to
`MediaLoader`. Only the selected/visible layout is loaded; its hero is prioritised,
nearby images follow, and below-fold images are observed with a 160px margin.
Hidden alternate layouts issue no image requests. Menu previews use thumbnail
copies; full-screen images can select a larger responsive copy.

Project-detail hero images load eagerly. Hover videos receive their source only
on interaction; content-video sources and posters are assigned near the viewport
with `preload="none"`. Image-effect canvases, shaders and textures are allocated
on first motion after the image arrives, rather than during initial rendering.
Retained pages resume their native images without allocating idle GPU contexts.

Image morphs compare canonical asset identities rather than responsive file
names. The cached moving copy is decoded before detaching the visible source.
At docking, `image-handoff.js` adopts that already-painted bitmap as a temporary
cover until the receiving responsive candidate has decoded and its GPU pass is
ready. Decode completions are tied to the current candidate and navigation;
Escape, another route, or disposal invalidates stale work.

Simple page transitions rebuild the home page, creating new `<img>` elements. `MediaLoader` therefore keeps one live `Image` for every URL that has finished loading, so a rebuilt image reuses the in-memory bitmap instead of revalidating over the network (Vercel serves static files with `max-age=0, must-revalidate`) and is ready before the page fades in. Failed loads are not kept, and `destroy()` releases them.
